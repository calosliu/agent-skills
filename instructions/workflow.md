# Implementation and verification

- Prefer the smallest complete solution: standard library, native platform features, and existing dependencies before new abstractions.
- Read project instructions and relevant code before editing. Keep project-specific commands and conventions in the project, not global guidance.
- Turn requested behavior into concrete acceptance checks. Run targeted tests and a direct behavioral probe; distinguish verified results from assumptions and blockers.
- Keep an active specification's progress and evidence current. Do not mark unfinished or untested work complete.
